프라이버시와 보안의 딜레마

❌ 기존 방식의 문제점

기존 Safe Browsing 방식은 URL을 서버로 보내 검사합니다. 하지만 E2E 암호화 메신저에서는 사용자가 어떤 링크를 클릭하는지 서버가 알 수 없어야 합니다. 이는 프라이버시와 보안이 상충하는 딜레마를 만듭니다.

✅ Meta의 해결책

Meta의 ABP는 암호학적 프리미티브(PIR, OPRF, ORAM)와 하드웨어 보안(AMD SEV-SNP)을 결합하여 서버가 사용자의 쿼리 내용을 알 수 없도록 하면서도 악성 URL을 탐지합니다.

기술 스택

🔗
URL Prefix Matching
URL은 정확히 일치하지 않습니다. "example.com/a/b"는 "example.com"이 블랙리스트에 있으면 위험합니다. 서버가 도메인별로 블록리스트를 버킷으로 그룹화하고, 클라이언트가 한 버킷을 가져와 로컬에서 프리픽스 매칭을 수행합니다.
Layer 1: Client-side Prefix Matching
⚖️
Ruleset-Based Bucket Balancing
링크 단축 서비스 등 특정 도메인에 블록리스트가 집중되면 버킷 크기가 불균형해집니다. 전처리 알고리즘이 "룰셋"을 생성하여 해시 전 경로 세그먼트 수를 조절하고, 버킷을 균등하게 재분배합니다.
Layer 2: Balanced Bucket Distribution
🔐
OPRF (Oblivious Pseudorandom Functions)
클라이언트가 각 URL 경로 세그먼트에 대해 블라인드된 OPRF 요청을 생성합니다. 서버가 블라인드된 출력으로 응답하면, 클라이언트만 언블라인딩하여 매치를 검증할 수 있어 서버는 쿼리 내용을 알 수 없습니다.
Layer 3: Cryptographic Obfuscation
🛡️
AMD SEV-SNP (TEE)
버킷 식별자가 AMD의 Secure Encrypted Virtualization을 통과합니다. 클라이언트가 원격 증명(attestation) 보고서를 검증하여 신뢰할 수 있는 코드가 TEE에서 실행 중임을 확인하고 암호화된 채널을 설립합니다.
Layer 4: Hardware-based Trusted Execution
🔀
ORAM (Oblivious RAM)
TEE 내에서도 메모리 접근 패턴이 정보를 누출할 수 있습니다. Path ORAM을 구현하여 서버가 모든 버킷에 접근하도록 강제함으로써, 실제로 어떤 데이터를 검색하는지를 은폐합니다.
Layer 5: Memory Access Pattern Hiding
🌐
OHTTP (Oblivious HTTP)
제3자 프록시가 요청에서 IP 주소 등 식별자를 제거한 후 서버로 전달합니다. 클라이언트의 신원과 쿼리를 분리합니다.
Layer 6: Network-level Anonymization

쿼리 처리 흐름

1

사용자 링크 클릭

사용자가 링크를 클릭하면 클라이언트가 룰셋을 적용하여 버킷 식별자를 계산합니다.

2

암호화된 요청 생성

TEE의 공개키로 버킷 ID를 암호화하고 URL 세그먼트별 OPRF 블라인드 요청을 생성합니다. 모든 요청을 고정 길이로 패딩하여 추적을 방지합니다.

3

프록시를 통한 전송

제3자 OHTTP 프록시를 통해 요청을 전송합니다. 프록시가 IP 주소를 제거하여 클라이언트의 신원을 보호합니다.

4

서버 처리

서버가 OPRF 응답을 사전 계산하고, 버킷 ID를 복호화한 후 ORAM으로 버킷을 검색합니다. 모든 버킷에 접근하도록 강제되어 실제 쿼리를 숨깁니다.

5

암호화된 응답

클라이언트의 공개키로 응답을 암호화하여 반환합니다. OHTTP 프록시는 응답이 어떤 쿼리에 대한 것인지 알 수 없습니다.

6

OPRF 언블라인딩

클라이언트가 OPRF를 언블라인딩하여 버킷 내용과 매칭을 확인합니다.

7

악성 URL 차단

매칭이 발견되면 경고를 표시하고 악성 링크 클릭을 차단합니다. 사용자의 행동 데이터는 어떤 단계에서도 서버에 전달되지 않습니다.

💡 설계 트레이드오프

덜 세분화된 버킷은 효율은 떨어지지만 쿼리 정보 누출이 줄어듭니다. 격자(lattice) 기반 암호 기법이 언젠가 샤딩의 필요성을 제거할 수 있겠지만, 현재 규모에서는 아직 비실용적입니다. 이 시스템은 프라이버시와 보안이 반드시 상충하는 것이 아님을 증명합니다. 올바른 암호학적 설계와 하드웨어 신뢰를 결합하면, 사용자의 행동을 노출하지 않으면서도 강력한 보안을 제공할 수 있습니다.

프라이버시 보장

🔒

서버 무지

서버는 쿼리에 대해 최소한의 비트(B bits)만 학습합니다. 전체 URL이나 사용자 의도는 알 수 없습니다.

✓

하드웨어 증명

AMD SEV-SNP의 원격 증명으로 신뢰할 수 있는 실행 환경을 보장합니다. 코드 무결성과 격리가 검증됩니다.

👁️

메모리 패턴 은폐

ORAM이 메모리 접근 패턴 분석을 차단하여 부채널 공격을 방지합니다.

🌐

신원 분리

OHTTP 프록시가 클라이언트의 IP와 쿼리 내용을 분리합니다. 추적 불가능합니다.

🎯 종합 요약

Meta의 Advanced Browsing Protection은 PIR, OPRF, ORAM, TEE, OHTTP라는 5가지 암호학적/하드웨어 프리미티브를 정교하게 조합하여, End-to-End 암호화를 깨지 않으면서도 Safe Browsing 수준의 보안을 달성합니다. 이는 단순히 기술적 혁신일 뿐만 아니라, 현대 웹의 보안과 프라이버시라는 오랜 난제를 푸는 근본적인 접근입니다.
