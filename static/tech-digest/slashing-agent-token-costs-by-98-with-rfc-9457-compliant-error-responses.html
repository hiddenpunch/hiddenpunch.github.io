에이전트 토큰 비용을 98% 줄이는 방법

RFC 9457 기반 구조화된 에러 응답으로 AI 에이전트의 토큰 낭비를 제거한다

HTML 14,252 토큰 → JSON 256 토큰 = 98.2% 절감

문제: AI 에이전트가 받는 에러 페이지

❌ 문제

  • AI 에이전트가 에러를 만나면 브라우저용 HTML 페이지를 받음
  • 46,645 bytes의 HTML을 파싱해야 함
  • 14,252 토큰을 소비
  • 어떤 조치를 취해야 하는지 모호함

✅ 해결

  • RFC 9457 Problem Details 포맷으로 구조화된 응답
  • 798 bytes의 마크다운 또는 970 bytes의 JSON
  • 221~256 토큰만 소비
  • 재시도 가능 여부와 구체적인 조치를 명확히 알려줌

토큰 절감 비교

HTML (브라우저용) 14,252 토큰 (100%)
Markdown (구조화) 221 토큰 (1.6%)
JSON (타입 제어) 256 토큰 (1.8%)
같은 에러(1015 Rate Limit)에 대해 포맷만 바꿔도 98% 이상 토큰을 절약합니다.

에이전트의 에러 처리 흐름

📥

1단계: 에러 응답 수신

에이전트가 RFC 9457 형식의 에러 응답을 받음

🔍

2단계: YAML/JSON 파싱

구조화된 응답을 파싱하여 주요 필드 추출

🔀

3단계: retryable 확인

retryable 필드를 확인하여 다음 단계 결정

✅

분기 1: retryable = true

retry_after 초만큼 대기 후 자동으로 재시도

❌

분기 2: retryable = false

owner_action_required 필드 확인

📢

분기 2-1: owner_action_required = true

소유자에게 에러 내용을 상세히 에스컬레이션

⛔

분기 2-2: owner_action_required = false

즉시 실패 처리 및 사용자에게 피드백 제공

핵심 권장사항

에이전트 런타임은 다음 HTTP 헤더를 기본값으로 설정해야 합니다:

Accept: text/markdown, */* (모델 워크플로우용)
또는
Accept: application/json, */* (타입 제어 흐름용)

이 기능은 네트워크 전체에 자동 적용되며, 사이트별 설정이 필요 없습니다.

요약

Cloudflare의 RFC 9457 구현은 에이전트 시대의 웹을 위한 기초 인프라입니다.
