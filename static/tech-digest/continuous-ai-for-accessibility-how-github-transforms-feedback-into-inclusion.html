AI로 접근성을 혁신하는 방법

GitHub이 접근성 피드백을 체계적인 개선으로 전환하는 자동화 워크플로우

📊 접근성 이슈의 구조적 문제

⚠️

기존 문제

  • 접근성 이슈가 백로그에 방치됨
  • 하나의 이슈가 네비게이션, 인증, 설정 등 여러 팀에 걸쳐 있어 소유권이 불명확
  • 흩어진 피드백으로 인한 데이터 손실
  • 지연된 응답 시간과 지켜지지 않는 약속
  • 접근성 전문가의 과도한 관리 부담
✨

GitHub의 해결

  • AI 자동화된 트리아지 워크플로우
  • Copilot이 메타데이터의 80%를 자동 분류 (40개 이상의 데이터 포인트)
  • 관리 시간 70% 절감
  • 이슈의 89%가 90일 내 해결
  • 일관되고 체계적인 대응

🔄 AI 접근성 워크플로우

1

📥 접수 (Intake)

토론 게시판(90%), 지원 티켓, SNS, 이메일로 피드백을 통합 접수합니다. 모든 채널의 피드백이 중앙집중식으로 관리되어 5영업일 내 확인됩니다.

2

🤖 Copilot 분석

GitHub Actions가 Copilot을 트리거하여 WCAG 매핑, 심각도, 영향 범위 등 40개 이상의 데이터 포인트를 자동으로 분류하고, 테스트 체크리스트와 권장사항을 코멘트로 제공합니다.

3

🔍 재현 확인

커뮤니티 매니저가 AI 제공 체크리스트를 사용하여 문제를 재현합니다. 키보드 네비게이션, alt-text, 스크린 리더 테스트 등을 체계적으로 수행합니다.

4

👨‍💼 접근성 팀 검토

전문가가 Copilot 분석을 검증하고, 수정 사항이 발견되면 이를 프롬프트 개선에 반영하여 AI의 정확도를 지속적으로 향상시킵니다.

5

🔗 감사 연결

보고된 이슈의 75-80%가 기존의 알려진 이슈와 매칭됩니다. 이를 통해 "고객 보고" 라벨로 우선순위를 조정하고 중복을 제거합니다.

6

✅ 루프 마감

사용자에게 해결 계획을 명확히 전달하고, 테스트 확인 후 이슈를 종료합니다. 해결 내용은 토론 게시판에 공개되어 커뮤니티와 투명성을 유지합니다.

7

🔄 지속 개선

PR을 통해 프롬프트를 업데이트하고, 주간 자동 스캔을 실행하며, 분기별로 해결 시간과 패턴을 리뷰하여 워크플로우를 최적화합니다.

💡 핵심 설계 철학

AI는 관리적 트리아지를 자동화하고, 인간은 실제 장벽을 해결하는 데 집중합니다. 모델 파인튜닝 대신, PR로 업데이트할 수 있는 Custom Instructions를 사용하여 누구나 AI 동작을 수정할 수 있습니다. 접근성은 일회성 감사가 아니라 자동화, AI, 인간 전문성이 결합된 살아있는 방법론입니다.

🛠️ 기술 스택

⚙️

GitHub Actions

워크플로우 오케스트레이션. 이슈 생성 시 자동으로 Copilot 분석을 트리거하고 결과를 코멘트로 게시합니다.

🤖

GitHub Copilot + Models API

LLM을 활용한 이슈 분석. WCAG 위반 분류, 심각도 판단, 영향 받는 사용자 그룹 식별을 자동화합니다.

📝

Custom Instructions

PR을 통해 업데이트되는 프롬프트 파일. 내부 접근성 정책, 컴포넌트 라이브러리 표준, WCAG 해석 가이드를 참조합니다.

📋

Issue Templates + Project Boards

표준화된 이슈 수집과 추적. 일관된 데이터 구조로 자동 분류의 정확도를 높입니다.

🎯 마무리

GitHub의 AI 접근성 워크플로우는 다른 조직도 복제할 수 있는 모델입니다. 이슈 템플릿, Copilot 인스트럭션, 자동화부터 시작하세요.
