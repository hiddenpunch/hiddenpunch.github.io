Pingora OSS의 HTTP 스머글링 취약점 분석

CVE-2026-2833, CVE-2026-2835, CVE-2026-2836 — 프록시와 백엔드 사이의 해석 불일치를 악용하는 공격

HTTP Request Smuggling이란?

HTTP Request Smuggling은 프록시와 백엔드 서버가 HTTP 요청의 경계를 다르게 해석할 때 발생하는 심각한 보안 취약점입니다. 이러한 해석 불일치를 악용하면 공격자는 하나의 요청 안에 두 번째 요청을 숨길 수 있습니다.

스머글링 공격의 결과는 치명적입니다. 공격자는 보안 제어를 우회하고, 사용자의 세션을 탈취하고, 캐시를 오염시킬 수 있습니다. 예를 들어 인증이 필요한 관리자 페이지에 접근하거나, 다른 사용자의 민감한 정보를 열람할 수도 있습니다.

Pingora OSS 배포에서 발견된 세 가지 취약점은 HTTP/1.1 프로토콜 사양(RFC 9112)의 미묘한 위반으로 인해 발생했으며, 프록시 구현의 정확성이 얼마나 중요한지를 보여줍니다.

3가지 취약점

CVE-2026-2833

Upgrade 헤더 오처리

Pingora가 101 Switching Protocols 응답을 기다리지 않고 단순히 Upgrade 헤더의 존재만으로 passthrough 모드로 진입합니다. 공격자가 두 번째 HTTP 요청을 파이프라이닝하면 이를 업그레이드된 스트림의 일부로 처리하여 보안 제어를 우회할 수 있습니다.

CVE-2026-2835

Transfer-Encoding 파싱 결함

HTTP/1.0 요청에 Transfer-Encoding 헤더를 허용하고, chunked 인코딩 검증이 미흡하며, close-delimited body를 허용하는 등 RFC 9112를 위반합니다. 이로 인해 프록시와 백엔드의 요청 경계 해석이 불일치하여 스머글링이 가능해집니다.

CVE-2026-2836

캐시 키 구성 문제

기본 캐시 키가 URI 경로만 사용하고 호스트 헤더와 스킴을 무시합니다. 결과적으로 서로 다른 호스트의 응답이 같은 캐시 엔트리를 덮어쓸 수 있어 캐시 오염 및 정보 유출이 발생합니다.

CVE-2026-2833 공격 흐름

1

공격자가 악의적인 요청 전송

공격자가 Upgrade: foo 헤더와 함께 GET 요청을 전송합니다.

⬇️
2

Pingora가 Passthrough 모드로 진입

Pingora는 101 Switching Protocols 응답을 기다리지 않고 즉시 passthrough 모드로 전환됩니다.

⬇️
3

공격자가 요청을 파이프라이닝

공격자가 같은 연결을 통해 두 번째 GET /admin 요청을 파이프라이닝합니다.

⬇️
4

Pingora가 잘못 전달

Pingora는 두 번째 요청을 업그레이드된 스트림의 일부로 백엔드에 전달합니다.

⬇️
5

보안 우회 성공

백엔드가 /admin에 대한 응답을 반환하고, 공격자는 인증 없이 관리자 리소스에 접근합니다. 🚨

수정 전 vs 수정 후

🔴 수정 전 (취약함)
  • Upgrade 헤더만으로 passthrough 모드 진입
  • HTTP/1.0 + Transfer-Encoding 허용
  • close-delimited 요청 body 허용
  • 캐시 키에 호스트 헤더 미포함
  • 스킴(http/https) 무시
  • 요청 경계 해석 불일치
🟢 수정 후 (안전함 — Pingora 0.8.0)
  • 101 Switching Protocols 수신 후에만 모드 전환
  • HTTP/1.0 + Transfer-Encoding 거부
  • close-delimited 요청 body 거부
  • 기본 캐시 키 구현 제거
  • 호스트 및 스킴 고려
  • RFC 9112 엄격 준수

💡 중요한 인사이트: Cloudflare CDN 고객은 안전합니다

Cloudflare CDN을 사용하는 고객은 영향을 받지 않습니다. Cloudflare의 CDN은 다운스트림에서 HTTP/1.1만을 지원하고 엄격한 프레이밍 검증을 수행하기 때문입니다. 그러나 Pingora를 독립적으로 배포하는 경우, 즉시 0.8.0으로 업그레이드해야 합니다. 자신의 인프라에서 Pingora를 역프록시로 사용 중이라면 최우선으로 패치를 적용하세요.

핵심 요약

HTTP Request Smuggling은 프록시 구현의 미묘한 차이에서 발생합니다. Pingora의 세 가지 취약점은 HTTP/1.1 스펙의 엄격한 준수 부족에서 비롯되었습니다. Pingora 0.8.0은 RFC 9112 사양을 엄격히 준수하여 이러한 문제를 완전히 해결했습니다. 안전한 배포를 위해서는 최신 버전으로의 즉각적인 업그레이드가 필수적입니다.

이 페이지는 Cloudflare 블로그 포스트를 기반으로 한 기술 설명 자료입니다.
